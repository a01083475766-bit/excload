## 1. 현재 주문연동 1차 목표

엑클로드의 주문연동 **1차 목표**는 쇼핑몰 주문을 가져와 **기존 엑클로드 흐름에 연결**하는 것이다.

기존에는 사용자가 주문 엑셀을 직접 업로드했다. 주문연동 후에는 그 입력 단계를 **쇼핑몰 API 주문조회**로 대체하거나 병행한다. 그 이후 단계(미리보기, 택배사 양식 다운로드, 택배사 프로그램 업로드, 송장 출력)는 **기존과 동일**하다.

### 기존 흐름

```
주문 엑셀 업로드
  → 엑클로드 미리보기
  → 택배사 양식 다운로드
  → 사용자가 택배사 프로그램에 업로드
  → 송장 출력
```

### 주문연동 후 흐름

```
쇼핑몰 주문조회
  → 엑클로드 미리보기
  → 택배사 양식 다운로드
  → 사용자가 택배사 프로그램에 업로드
  → 송장 출력
```

**핵심**: 기존 기능을 버리지 않고, 「주문 엑셀 업로드」를 「쇼핑몰 주문조회」로 **대체·추가**하는 구조다.

## 2. Shopify 현재 상태

Shopify는 코드 기준 **1차 MVP(주문조회) 구현 완료** 상태이며, **운영 잠금(feature flag false)** 으로 실제 테스트를 대기 중이다.

### 완료된 것

| 영역 | 내용 |
|------|------|
| OAuth | connect/callback route, shopDomain 검증, HMAC·state 검증 |
| 보안 | token 암호화 저장 (`shopify-account.ts`) |
| API | GraphQL Admin API 주문조회 client (`client.ts`, `orders.ts`) |
| Route | fetch-orders, test (feature flag gate) |
| 변환 | Shopify 주문 → OrderStandardFile 매핑 |
| 미리보기 | **주문 1건 = 1행** (배송/택배 업로드 기준) |
| 상품 표시 | lineItems 여러 개 → 상품요약 문자열 (`상품명` 열) |
| 운영 잠금 | `SHOPIFY_INTEGRATION_ENABLED` 기본 **false** |

### 아직 하지 않은 것

| 영역 | 내용 |
|------|------|
| 실제 연동 | 테스트 스토어 연결, 실제 Shopify API 호출 |
| 운영 | Production DB migration 적용, Vercel env 등록 |
| UI | Shopify 클릭 가능 처리, 일반 사용자 오픈 |
| 후속 기능 | 송장전송, 배송조회, 주문상태 변경 |

### 상태 요약

```
코드 구현 완료
  → 운영 잠금 상태 (feature flag false)
  → 실제 Shopify 테스트 준비 대기
```

상세 절차는 [shopify-test-runbook.md](./shopify-test-runbook.md) 참고.

## 3. Shopify 실제 테스트 전 준비사항

Shopify 실제 테스트에는 아래 준비물이 필요하다.

### 3.1 준비물

| 구분 | 항목 |
|------|------|
| Partners | Shopify Partner 계정, 테스트 스토어, 앱 생성 |
| Credential | Client ID, Client Secret |
| Redirect | Partners Dashboard 등록 + env |
| Vercel env | `SHOPIFY_CLIENT_ID`, `SHOPIFY_CLIENT_SECRET`, `SHOPIFY_OAUTH_REDIRECT_URI`, `SHOPIFY_INTEGRATION_ENABLED`, `SHOPIFY_API_VERSION`, (선택) `SHOPIFY_OAUTH_STATE_SECRET` |
| DB | Production `OrderIntegrationProvider.SHOPIFY` enum migration 적용 **승인** |

### 3.2 앱 설정

**Redirect URL**

```
https://www.excload.com/api/order/integration/shopify/callback
```

**Scope**

- `read_orders` **만** 사용
- `read_all_orders` **사용 금지** (60일 초과 이력·Partner 별도 승인 — 2차 이후)

### 3.3 활성화 순서

1. Shopify Partner 계정 준비  
2. 테스트 스토어 생성  
3. Shopify 앱 생성  
4. Redirect URL 등록  
5. Client ID / Secret 확보  
6. Production DB migration 적용 여부 **승인**  
7. Vercel env 등록  
8. 테스트 계정 기준으로만 `SHOPIFY_INTEGRATION_ENABLED=true`  
9. OAuth 연결 테스트 (`connect` → `callback`)  
10. token 저장 확인  
11. `fetch-orders` 테스트  
12. OrderStandardFile·previewRows 결과 확인  
13. 문제 없을 때 **관리자 UI** 연결 검토  
14. 마지막에 일반 사용자 오픈 검토  

### 3.4 절대 금지

| 금지 | 사유 |
|------|------|
| Production DB migration 전 feature flag `true` | enum 없으면 계정 저장 실패 |
| Client ID/Secret 없이 route 활성화 | OAuth·HMAC 불가 |
| UI 먼저 열기 | 미준비 상태 사용자 혼란 |
| `read_all_orders` 추가 | 1차 범위·심사 리스크 |
| 실제 사용자 대상 선오픈 | 관리자·테스트 검증 전 |

## 4. 주문조회 이후 기본 사용 흐름

엑클로드의 **전체 사용 흐름**(주문조회 이후)은 아래와 같다.

### 1단계: 주문조회

```
쇼핑몰 API
  → 주문 가져오기
  → 엑클로드 미리보기
  → 택배사 양식 다운로드
```

### 2단계: 택배사 프로그램 사용

```
사용자
  → 다운로드한 택배사 양식을 택배사 프로그램에 업로드
  → 송장 출력
  → 택배사 프로그램에서 송장번호 포함 파일 다운로드
```

### 3단계: 송장파일 업로드

```
사용자
  → 송장번호가 포함된 택배사 파일을 엑클로드에 업로드
  → 엑클로드가 기존 주문과 송장번호를 매칭
```

(설계 초안: [송장번호변환-설계.md](../송장번호변환-설계.md))

### 4단계: 쇼핑몰 송장 업로드 파일 생성

```
엑클로드
  → 주문정보 + 송장번호를 합쳐
  → 쇼핑몰별 송장 업로드용 엑셀 다운로드 제공
```

### 5단계: 주문연동된 쇼핑몰 — API 송장전송 (선택)

연동된 쇼핑몰의 경우, 엑셀 다운로드와 **병행**하여 API로 송장번호를 직접 전송할 수 있다.

| 쇼핑몰 유형 | 제공 기능 |
|-------------|-----------|
| API 연동 **없음** | 송장 업로드용 엑셀 다운로드만 |
| API 연동 **있음** | 송장 업로드용 엑셀 다운로드 **+** API 송장전송 |

**기존 다운로드 기능은 항상 유지**한다.

## 5. 송장전송 기능의 핵심 방향

송장전송은 쇼핑몰 **주문·배송 상태를 실제로 변경**하는 기능이므로 신중하게 구현한다. **즉시 전체 자동전송은 하지 않는다.**

### 권장 흐름

```
송장파일 업로드
  → 주문 매칭
  → 전송 전 검증
  → 전송 가능 목록 표시
  → 사용자가 선택
  → 선택한 주문만 송장전송
```

### 전송 전 검증 예시

- 주문번호 매칭 여부  
- 수취인 / 전화번호 / 주소 일치 여부  
- 택배사 인식 여부  
- 송장번호 존재 여부  
- 송장번호 중복 여부  
- 이미 전송된 주문 여부  
- 취소 주문 여부  
- 송장번호 형식 오류 여부  

---

## 6. 송장번호 매칭에 필요한 데이터

### 6.1 주문조회 시점에 보존할 값

| 필드 | 용도 |
|------|------|
| 엑클로드 내부 주문 ID | 이력·매칭 SSOT |
| 쇼핑몰 provider | 몰 구분 |
| 쇼핑몰 계정 ID | 연동 계정 구분 |
| 쇼핑몰 주문번호 | 사용자 표시·매칭 키 |
| 쇼핑몰 원본 주문 ID | API 재호출·송장전송 |
| 쇼핑몰 주문상품번호 / line item ID | 상품별 송장(2차) |
| 수취인명, 전화번호, 주소 | 매칭·검증 |
| 상품요약, 수량 | 미리보기·검증 |
| 배송메모, 주문일, 주문상태 | 표시·취소 제외 |
| 원본 API 식별자 | fulfillment 등 후속 API |

> **Shopify 1차**: 미리보기는 주문 1행·상품요약 문자열. line item 상세는 OrderStandardFile row에 별도 필드 없음 — 2차 송장전송 시 `order.id`·line item GID 보존 설계 필요.

### 6.2 송장파일 업로드 후 필요한 값

| 필드 | 용도 |
|------|------|
| 택배사명, 택배사 코드 | 쇼핑몰 API 변환 |
| 송장번호 | 전송 본문 |
| 송장 발급일 | 이력 |
| 송장파일 원본 행 번호 | 오류 추적 |
| 매칭 상태, 전송 상태, 실패 사유 | UI·재시도 제어 |

## 7. 내부 관리번호 필요성

주문조회 후 다운로드·이력마다 **엑클로드 내부 관리번호**를 부여하는 것이 안전하다.

**예**: `EXC-20260709-000001`

### 용도

- 주문조회 결과와 다운로드 이력 연결  
- 택배사 송장파일 재업로드 시 매칭  
- 중복 송장전송 방지  
- 오류 발생 시 추적  
- 동일 주문 재다운로드 시 구분  

### 주의

**엑셀 행 순서만**으로 매칭하면 위험하다.  
`주문번호 + 수취인 + 전화번호 + 주소 + 내부 관리번호`를 함께 쓰는 방향이 안전하다.

### 예상 구조

```
엑클로드 표준 택배사 코드
```

## 9. 기능 단계 구분

### 1차: 주문조회 연동 ✅ (Shopify 코드 완료, 운영 대기)

**목표**

```
쇼핑몰 주문조회 → 엑클로드 미리보기 → 택배사 양식 다운로드
```

| 포함 | 미포함 |
|------|--------|
| 주문조회, 미리보기, 택배사 양식 변환 | 송장전송, 배송조회 |
| 주문 1건 = 미리보기 1행 | 주문상태 변경, 발주확인 |
| 상품 여러 개 = 상품요약 문자열 | 클레임 처리 |
| 중복·취소 표시/제외 기준 (몰별) | |

### 2차: 송장파일 업로드·매칭

**목표**

```
택배사 송장파일 → 엑클로드 업로드 → 주문과 송장번호 매칭 → 쇼핑몰 송장 업로드용 엑셀
```

| 포함 |
|------|
| 송장파일 업로드, 송장번호·택배사 컬럼 자동 인식 |
| 주문번호/수취인/전화/주소·내부 관리번호 매칭 |
| 매칭 결과 미리보기, 오류/중복 표시 |
| 쇼핑몰별 송장 업로드용 엑셀 다운로드 |

### 3차: 쇼핑몰 API 송장전송

**목표**: 주문연동된 쇼핑몰에 한해 송장번호를 API로 직접 전송.

| 포함 | 미포함 |
|------|--------|
| 전송 전 검증, 사용자 선택 전송 | 완전 자동 전체 전송 |
| 쇼핑몰별 택배사 코드 변환 | 주문상태 임의 변경 |
| 성공/실패 저장, 재전송 방지, 재시도 | 클레임 자동화 |

**Shopify**: `write_fulfillments` scope·fulfillment create API — 1차 OAuth 범위 **제외**. 3차 착수 시 별도 scope·설계.

### 4차: 배송조회

**목표**: 송장번호 기준 배송 상태 조회. **송장번호 확보 이후** 단계.

| 포함 후보 |
|-----------|
| 배송중/배송완료 조회, 택배사별 추적 |
| 쇼핑몰 배송상태 vs 택배 상태 비교 |
| 배송완료 알림 후보, 장기 미배송 목록 |

## 11. 현재 결론

엑클로드에 가장 현실적인 순서:

1. **주문조회 연동**을 우선 완성한다. (Shopify: 코드 완료 → 실제 테스트 대기)  
2. 기존 **미리보기 / 택배사 양식 다운로드** 흐름과 연결한다.  
3. **송장파일 업로드** 후 주문과 송장번호를 **매칭**하는 기능을 만든다.  
4. API 연동 없는 쇼핑몰은 **송장 업로드용 엑셀** 다운로드를 제공한다.  
5. API 연동 있는 쇼핑몰은 **엑셀 + API 송장전송**을 병행 제공한다.  
6. **배송조회**는 송장번호 확보 이후 구현한다.  

### 핵심 방향

```
기존 엑클로드 기능 유지
  + 주문조회 자동화 추가
  + 송장파일 매칭 추가
  + 연동 쇼핑몰 송장전송 추가
  + 배송조회는 후순위
```
